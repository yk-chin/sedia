---
name: ship-check
description: 部署或演示前对项目做一次面向评审现场的可靠性自检。当用户说"检查一遍""能不能上线""ship check""上线前看看"时使用。
---

按顺序执行，每一步必须给出**实际证据**（命令输出、截图），不许说"应该没问题"。

1. 运行 `npm run build`，贴出完整结果。失败就停下来报告，不要继续。
2. 用浏览器 MCP 打开**线上 URL**（不是 localhost），照 `docs/SPEC.md` 的"核心流程"走完每一步，每步截图。
3. 检查这些必须存在的状态：
   - 每个异步操作有 loading（skeleton，不用转圈）
   - 每个列表有空状态文案 + 一个引导操作
   - 每个可能失败的调用有错误态，文案是人话，不暴露堆栈
4. 把浏览器宽度调到 375px，重跑一遍，检查横向滚动和元素重叠。
5. 打开 Console，报告所有 error 和 warning。
6. 运行 `git diff` 和 `git log -p | grep -Ei "AIza|sk-|SERVICE_ROLE"`，确认没有密钥。
7. 确认 `DEMO_SAFE_MODE` 开关仍然存在且可用：把 `.env.local` 里改成 true，重启 dev server，确认界面仍然正常。

输出格式：
- 🔴 会导致演示当场翻车的项（放最前面）
- ❌ 其他失败项（文件:行号 + 一句话原因 + 最小修复方案，不要重构）
- ✅ 通过项（简单列出即可）
